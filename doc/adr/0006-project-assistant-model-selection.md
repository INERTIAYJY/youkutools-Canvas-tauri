# ADR-0006：项目默认文本模型驱动对话助手与 Agent

## 状态

Accepted（阶段一仅统一确定性模型优先级，自动能力路由与视觉输入分阶段实施）

## 背景

项目设置已经保存文本、图片、视频和音频默认模型，但文本默认模型目前只在创建文本节点时生效。对话助手、Agent Runtime、上下文预算和独立聊天窗口仍读取应用级 `assistantModelId`，导致同一项目内“默认文本模型”与实际助手模型不一致。

用户还需要在后续阶段让 Agent 根据结构化能力与可编辑描述自动选择模型，并让视觉模型直接读取图片或为纯文本模型提供持久化图片描述。上述能力都要求先建立唯一、可预测的项目级助手模型基线。

## 决策

1. 对话助手与 Agent 的确定性文本模型顺序固定为：当前项目 `settings.defaultModels.text` → 应用 `config.assistantModelId`。
2. 项目模型必须能在当前配置中解析并可调用；无效、已隐藏或连接不可用时安全回退到应用模型，而不是阻断旧项目。
3. 对话输入区的文本模型选择器展示当前项目的有效选择；用户更改时写入当前项目默认文本模型。没有活动项目时才修改应用级助手模型。
4. 主窗口、独立窗口、实际请求和上下文预算必须复用同一候选顺序，禁止各自实现不同优先级。
5. 本阶段不增加自动路由、不修改模型描述、不发送图片、不升级 IndexedDB；后续阶段建立在该选择边界上。

## 后果

### 正面

- 项目设置中的默认文本模型与实际对话、Agent 调用一致。
- 项目切换可自然切换助手模型，不污染其他项目或全局默认。
- 无效项目配置具有兼容回退，旧项目不会因模型被删除而无法对话。

### 负面

- 用户在项目内切换助手模型会更新项目默认文本模型，也会影响新建文本节点的默认模型。
- 阶段一仍不能根据任务特性自动挑选模型，也不能读取视觉素材。

### 中性

- 应用级 `assistantModelId` 继续存在，作为无项目场景和旧项目的回退值。

## 备选方案

### 继续让助手只读取应用默认

拒绝。项目设置会继续展示一个与实际助手调用无关的“文本默认模型”。

### 为每个对话新增独立模型字段

暂不采用。会引入新的持久化与同步语义，并削弱用户要求的项目默认基线；未来可作为显式单轮覆盖另行设计。

### 立即实现描述驱动的自动路由

暂不采用。结构化视觉能力、成本约束和失败回退尚未建立，直接让模型按自然语言描述路由不可验证。
