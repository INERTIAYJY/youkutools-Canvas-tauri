# ADR 0007：项目级视觉上下文与描述缓存

- 状态：已接受
- 日期：2026-08-13

## 背景

对话输入中的图片引用此前只在部分文本生成路径解析，Agent 的 OpenAI 兼容请求仍可能只看到字符串标记。与此同时，纯文本模型无法直接消费图片，但仍需要基于项目素材完成分析与创作。

## 决策

1. 对话和 Agent 在请求发送前统一解析用户显式 `@` 图片引用。
2. 支持视觉输入的文本模型接收受大小与数量限制的 Base64 data URL，不依赖第三方临时图床。
3. 纯文本模型不接收图片字节；先由项目视觉模型生成客观描述，再把描述作为不可信素材说明注入当前请求。
4. 描述以图片内容 SHA-256 指纹绑定到项目；剧集分集复用剧集根项目的缓存。图片未变化时复用，图片替换时产生新指纹，素材从画布移除时不删除历史描述。
5. 缓存只持久化描述、指纹和模型元数据，不持久化图片 Base64、本地路径或凭据。删除普通项目或整部剧时随项目域数据清理。
6. 模型是否支持图片输入优先使用用户配置的 `inputModalities`，旧配置才回退到有限的模型 ID 识别。

## 影响

- IndexedDB 升级到 v19，新增 `projectVisualDescriptions` store。
- 项目设置新增视觉理解模型和自主媒体自动路由开关。
- 厂商模型配置新增用途说明与图片输入能力声明。
- Web/桌面请求都保留统一的图片数量、单图大小和总大小限制。

## 回滚

代码可以停止读取该 store 并移除请求前视觉准备，但数据库版本不能降级；保留空 store 避免已有客户端出现 `VersionError`。
