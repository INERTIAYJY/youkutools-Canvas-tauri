# 角色库设计方案

## 目标

为画布增加独立、直观的角色库入口。角色库同时提供“本项目”和“永久保存”两个范围，支持一个角色保存多张参考图、每图提示词、图片用途和头像裁剪。图片节点可通过右键加入新角色或已有角色，保存成功后默认隐藏原节点，减少画布复杂度。

## 已确认的产品决策

- 左侧栏在资产入口附近增加独立“角色库”入口。
- 角色库使用“本项目 / 永久保存”两个一级标签，默认打开“本项目”。
- 项目角色与永久角色采用独立副本；双方复制后不自动同步。
- 一个角色支持多张参考图，可标记为主视觉、头像、全身、表情、多视角、服装或其他。
- 每张参考图保留独立提示词和来源信息；一个角色只有一个主视觉和一个默认头像。
- 后续图片可选择加入已有角色或创建新角色，不自动合并。
- 图片节点添加成功后默认隐藏；关联连线同时暂时隐藏。
- 隐藏操作可撤销，角色卡提供“显示并定位节点”。
- 删除项目角色卡时恢复仍由该角色收纳的隐藏节点。

## 界面结构

角色库使用与资产管理一致的全尺寸浮层。顶部包含标题、范围标签、搜索和新建按钮；上半区展示所选角色的参考图画廊、当前大图、角色主提示词与当前图片提示词；下半区使用横向头像列表切换角色。

永久角色不依赖任何项目节点。“添加到本项目”复制完整角色卡和参考图；“永久保存”将项目角色图片复制到全局资产目录，并复制结构化角色数据。

## 数据边界

项目角色继续保存在 `CanvasProject.dramaAssets`。现有单图角色库升级为多图结构，旧 `imageNodeId` 和 `imageUrl` 在读取时规范化为第一张参考图，同时保留旧字段作为迁移期兼容入口。

永久角色使用独立 IndexedDB object store。图片文件通过 `fileService` 写入全局资产目录；持久化角色数据只保留稳定资产标识、相对定位信息和必要展示 URL，不依赖项目节点或项目绝对路径。

## 原子性与失败处理

添加顺序固定为：校验图片、保存或复制图片、写入角色卡、隐藏节点、保存项目。只有角色卡持久化成功后才隐藏节点。保存失败时节点保持可见并显示错误；同一节点重复加入同一角色时更新原参考图，不创建副本。

## 验收重点

- 旧项目角色可无损读取并显示为单张参考图。
- 切换项目只改变“本项目”，不影响“永久保存”。
- 多图用途、提示词、主视觉和头像裁剪可持久恢复。
- 项目与永久副本独立编辑。
- 隐藏节点、关联连线、撤销、恢复和定位行为一致。
- 任一持久化步骤失败时不隐藏节点、不产生半成品角色卡。
