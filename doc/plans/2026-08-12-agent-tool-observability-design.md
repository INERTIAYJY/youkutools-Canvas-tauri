# Agent 工具调用可观测性设计

## 目标

让用户在 Agent 任务时间线和审批卡中看清楚“调用了什么、传入什么、将改变什么、最终得到什么”，重点覆盖媒体生成、画布节点创建与节点修改，同时不持久化密钥、本地绝对路径、完整媒体 URL 或未裁剪的不可信正文。

## 架构选择

采用结构化、脱敏、可持久化的展示快照，而不是直接保存工具原始 JSON。`AgentToolDefinition` 增加输入展示构建器，`AgentToolExecutionResult` 可返回结果展示快照；Agent 的普通执行路径与多轮执行路径都在同一时机生成并保存快照。快照只包含短文本字段、数字参数、节点/资产标识和安全的引用描述，旧任务缺少新字段时继续按原摘要渲染，因此无需提升 IndexedDB schema。

媒体工具在审批前把用户参数与项目默认设置解析成完整的有效参数。比例、分辨率和时长进入工具 schema、审批快照与 `MediaGenerationIntent`，执行时只消费已锁定值，避免“确认内容”和“实际请求”不一致。参考素材以节点 ID、标签和类型保存；缩略图在界面渲染时根据当前 Store 解析，不持久化 URL 或路径。

画布创建快照展示每个节点的类型、名称、坐标来源和提示词预览。节点更新在执行前读取目标节点，执行后形成字段级前后差异；模型只收到既有精简结果，用户界面收到额外的审计详情。工具执行失败时保留输入快照和错误摘要，不伪造结果详情。

## UI

`AgentStepCard` 和 `AgentApprovalCard` 复用一个紧凑的详情组件。默认展示现有摘要，展开后按“参数、参考素材、变更、结果”分组。提示词与正文仅展示受限预览；参考素材仍存在时显示本地缩略图，不存在时显示“素材已不可用”。界面同时适配暗色和浅色 token，并支持键盘展开。

## 失败与回滚

- 展示快照构建失败不阻断工具执行，退化到现有 `inputSummary`。
- 媒体参数不合法时在 schema/authorize 阶段拒绝，不进入付费执行。
- 旧任务和未实现详情的工具继续显示原摘要。
- 回滚顺序：UI 详情组件 → 工具展示快照 → 媒体显式参数；所有新增持久化字段均为可选。
