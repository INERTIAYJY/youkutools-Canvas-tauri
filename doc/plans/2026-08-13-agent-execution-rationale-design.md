# Agent 实时执行依据视图设计

## 目标

在 Agent 任务时间线中提供可折叠、随任务状态实时更新的“执行依据”，让用户知道 Agent 正在分析什么、为什么允许或拦截某个工具、工具得到什么结果，以及接下来为何继续或暂停。

## 方案选择

采用可验证事件派生方案。视图只读取已经持久化并经过白名单裁剪的 `AgentEvent`，再按 `callId` 关联现有 `AgentStep` 的脱敏输入与结果摘要。它不读取厂商私有 `reasoning_content`，不展示模型隐藏思维链，也不额外调用模型生成摘要。

相比直接透传厂商推理字段，该方案跨 Provider 稳定，不会误把隐藏思维或敏感上下文暴露给界面；相比额外摘要模型调用，它没有新增费用、延迟或失败点。事件由现有 Agent Journal 实时写入 Zustand 和 IndexedDB，因此界面自然随模型轮次、权限判断、审批和工具执行更新，无需新增流协议或数据库版本。

## 数据与界面

新增纯函数 `buildAgentExecutionRationale(task)`，把事件转换为最多 16 条展示项：分析请求、提出工具、权限判断、开始执行、结果、用户确认、画布回退点和任务状态。工具名称优先使用步骤标题；输入与结果只使用现有脱敏摘要。权限原因由本地固定 Policy 语义映射生成，不接受模型文本。

时间线新增 `AgentExecutionRationale` 折叠区。活动任务默认展开，终态任务默认折叠；用户可以随时切换。摘要行显示当前可验证状态和条目数量，正文顶部明确标注“不包含模型隐藏思维”。不同状态同时使用图标和文字，不只依赖颜色。

## 安全、兼容与回滚

- 不保存新的正文，不扩大 `AgentEventData` 白名单。
- 不显示用户原始消息、Skill 正文、工具原始 JSON、路径、密钥或媒体 URL。
- 旧任务没有事件时不显示该区域；已有事件和步骤无需迁移。
- 回滚时移除时间线组件和派生服务即可，不涉及数据清理、IndexedDB、Tauri 或 Provider 协议。
