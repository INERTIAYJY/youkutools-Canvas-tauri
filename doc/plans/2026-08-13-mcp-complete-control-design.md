# MCP 全面控制能力设计

## 目标与边界

MCP 在现有 53 项候选工具和项目管理工具基础上，补齐应用界面观测、窗口与画布视口控制、截图，以及已有业务 Store 尚未暴露的完整管理能力。所有新增工具只在 `mcp-control-*` 会话中发现和执行，继续经过本地 schema、固定 MCP 自主 Policy、工具授权、审计任务和脱敏输出；无须应用内确认，但不会获得任意 Shell、任意 HTTP、任意系统窗口、任意路径或审批解决能力。

本次不新增依赖、不修改 `tauri.conf.json`。截图复用现有 `html-to-image`，通过各 AI Canvas Webview 内的响应器捕获可见 DOM；结果压缩后作为 MCP `image` 内容返回，不落盘、不进 IndexedDB、不进入操作日志。设置中的凭据输入和带敏感标记的元素在截图前临时遮盖。结构化布局状态是主要观测接口，截图仅用于视觉核对。

## 架构与数据流

新增 MCP 专用工具域：UI/窗口/视口工具调用轻量运行时服务；业务管理工具只编排现有 Zustand Action 和持久化服务，不复制事务逻辑。Canvas 将 React Flow 实例的只读快照与受控操作注册进内存服务，不把运行时对象写入 Store。每个 Webview 注册截图响应器，主窗口 MCP 控制服务按固定窗口标签转发请求并限制尺寸、质量和响应体积。

工具按领域拆分为界面、工作流、Skill、预设与风格、记忆、剧集素材、会话任务、高级画布和历史。读取结果只返回完成操作所需的结构化摘要；密钥、本地绝对路径、完整正文、运行时控制器和 MCP 令牌始终排除。写操作复用既有历史提交、项目校验、剧集共享素材规则和任务中止逻辑。

## 风险与验证

DOM 截图不包含操作系统窗口阴影或被其他应用遮挡后的真实桌面像素，但能稳定表达 AI Canvas 当前可见内容；未加载或最小化的 Webview 可能无法截图，工具将返回稳定错误而不猜测。图像必须压缩到桥接帧上限以内，否则自动降低尺寸或质量。所有工具先以失败测试固定 schema、MCP 专用可见性、授权、Store Action 编排和脱敏规则，再实现最小代码；每批运行定向测试、类型检查、定向 ESLint、差异与 UTF-8 检查，最终运行全量测试和生产构建。
