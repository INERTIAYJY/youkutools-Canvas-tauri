# v0.11.13 发版准备：森之灵 CLI-only 与标签 CI 调度修复

## 背景

v0.11.11 Release 在 `Resolve immutable release source and notes` 由于 release title 仍指向 v0.11.9 失败；v0.11.12 修复 title 后通过 metadata resolve，但因 fork 的 CI 只在 `push tags` 触发、API 未产生标签 CI run，Release proof 持续等待并超时。v0.11.11/v0.11.12 标签均不可移动，本补丁为 v0.11.13。

## 变更

- CI 增加 `workflow_dispatch.release_tag` 输入。手动运行只能选择 `refs/tags/vX.Y.Z`，输入必须与当前 ref 完全一致；仍核对 checkout SHA、正式 tag 和默认分支祖先，检查计划沿用全量/受影响范围门禁。
- Release workflow 仅接受同仓库、同 CI workflow path、同稳定 tag/head SHA 的 push 或经上述代码校验的 workflow_dispatch run；继续要求所有必需 jobs 同 SHA 成功及有效前端 artifact。
- 修复使用真实远端失败证据：v0.11.11 run `44687246222` 在 title resolve 失败；v0.11.12 run `44689945739` resolve 成功，等待源码 CI 证明后超时，publish jobs skipped。
- 保留森之灵 CLI-only认证：不收集/传递 API Token，不把 `SEEDLING_TOKEN` 传入 CLI；旧 Token 惰性保留。

## 验证和发布

- 必须运行 `npm run ci`，重点验证 ci-source-plan 与 release-workflow 对受控 dispatch、错误 ref、错误 tag、错 SHA 的拒绝行为。
- 核对 README/Cargo/package/lock/Tauri 版本、`.github/release-title.txt` 和 `.release-notes.md` 均指向 0.11.13。
- 按仓库发布规则原子推送 master 与 v0.11.13。推送后 Actions Summary 应显示 tag CI（全量或具可信基线的受影响模式）、前端 artifact id/hash 与同 SHA Release 质量门；签名构建完成后再验证 Release 公开及 latest.json。
- 不在本机运行安装包；用户在另一台旧版本客户端自行验证热更和 Seedling CLI 登录。
