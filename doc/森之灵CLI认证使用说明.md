# 森之灵（Seedling）认证使用说明

> 适用对象：使用 AI Canvas 桌面版的最终用户。
> 本文说明如何完成森之灵（Seedling）AI 视频生成能力的认证，认证完成后即可在视频节点与对话中生成森之灵视频。

## 一、森之灵是什么

森之灵（Seedling）是 AI 视频生成平台，官方地址：`https://seedling.p.ykss.com.cn`。

AI Canvas 已内置森之灵接入：

- **视频节点**：模型选择器可选森之灵模型，按模型能力约束时长 / 分辨率 / 比例 / 参考图 / 配乐。
- **对话 Agent**：对话中通过 `@` 引用森之灵模型即可生成视频。

## 二、接入原理（先读这一段）

森之灵在应用内**统一通过 CLI（命令行工具）通道**发起所有视频生成请求。应用启动时会自动检测本机 CLI，未安装时可在设置页一键安装。

**认证凭据有两种，完成任一种即可使用**：

| 方式 | 凭据 | 有效期 | 适用场景 |
|---|---|---|---|
| 方式 A | CLI 浏览器授权登录（登录态） | 90 天 | 普通用户，推荐 |
| 方式 B | API Token（机器令牌） | 永久 | 多台机器 / 长期使用 / 无人值守 |

> ⚠️ 重要：两种方式**都是认证凭据，不是独立的接入通道**。无论用哪种方式认证，视频生成请求都由 CLI 发起：
> - API Token 以 `SEEDLING_TOKEN` 环境变量注入 CLI 使用，**不能脱离 CLI 单独调用平台接口**；
> - CLI 未安装或不可用时，API Token 也无法生效。

## 三、认证方式 A：CLI 浏览器授权登录（推荐）

1. 打开 AI Canvas → **设置 → 森之灵**。
2. 查看「CLI 状态」区块：
   - 显示「已找到」：直接进入下一步；
   - 显示「未找到」：点击 **「安装 CLI」**，等待安装完成（应用会自动从官方源下载并缓存到本机）。
3. 在「认证方式 A — CLI 浏览器授权登录」区块点击 **「开始浏览器授权登录」**。
4. 出现授权信息后点击 **「打开」** 跳转浏览器，在页面中确认显示的**配对码**。
5. 授权完成后回到应用，该区块显示「CLI 已登录（用户名）」，下方「可用模型」列表自动加载森之灵模型。

- 登录态由 CLI 持久化保存，**有效期为 90 天**，到期后重新执行一次浏览器授权即可。
- 登录态与应用内下载的 CLI、系统已安装的 CLI 共用同一份配置文件，任一处登录，两边都生效。

## 四、认证方式 B：API Token（机器令牌）

适合需要在多台机器使用或长期无人值守的场景。

1. 浏览器打开森之灵 Web 端 `https://seedling.p.ykss.com.cn`，登录账号。
2. 点击右上角**用户头像 → API 访问令牌 → 创建**，复制生成的 Token。
3. 回到 AI Canvas → **设置 → 森之灵**，在「认证方式 B — API Token」区块粘贴 Token，点击 **「保存 Token」**。
4. 看到「API Token 已保存（经 CLI 使用）」提示后，「可用模型」列表自动加载森之灵模型。

注意事项：

- Token 为机器令牌，**永久有效**，无需像方式 A 一样定期续期。
- Token 同样需要 CLI 才能使用：应用把 Token 作为 `SEEDLING_TOKEN` 环境变量注入 CLI，由 CLI 发起请求；请确保「CLI 状态」显示「已找到」，否则先点击「安装 CLI」。
- 如需停用，在设置页点击 **「清除」**，之后回退使用方式 A 的 CLI 登录态。

## 五、常见问题

| 问题 | 处理办法 |
|---|---|
| CLI 状态显示「未找到」 | 点击「安装 CLI」按钮，应用自动下载安装；安装完成后自动检测 |
| 已配置认证但模型列表为空 | 确认已完成方式 A 或方式 B 任一种认证，点击「可用模型」旁的「刷新」 |
| 填了 API Token 仍提示未认证 | 确认 CLI 已安装；Token 必须经 CLI 才能使用，CLI 缺失时 Token 不生效 |
| 方式 A 登录后提示「未登录或令牌失效」 | 登录态 90 天过期，重新执行一次浏览器授权登录 |
| 下载视频失败或任务卡住 | 在「任务中心」查看任务状态；网络异常时重试一次 |

## 六、安全提示

- **API Token 等同账号凭据**：请勿把 Token 发送到群聊、截图、文档或任何公开位置。
- 如怀疑 Token 泄露：登录森之灵 Web 端 → 头像 → API 访问令牌 → 删除该 Token 并重新创建，然后在应用内重新保存。
- 应用内 Token 保存在系统安全存储（Rust 凭据存储），不会写入聊天记录、操作日志或导出文件；应用也不会在任何日志中记录 Token 内容。
